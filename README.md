# Organa — Business Data Management SystemOrgana is a web-oriented data management system designed for service-based businesses.  The system allows organizations to manage clients, services, appointments, employees, financial analytics, audit logs, and structured business data in a centralized workspace.The project was developed as part of a qualification thesis on the topic of building a web-oriented information system for data management using modern web technologies.---## OverviewOrgana is built as a multi-tenant web application. Each registered business creates its own organization workspace, and all business data is isolated within that organization.The system supports:- organization-based data isolation;- user authentication;- role-based access control;- client management;- service and category management;- appointment scheduling;- appointment status tracking;- appointment conflict validation;- actual service price tracking;- financial analytics;- CSV data export;- audit logging;- REST API endpoints;- Docker-based local deployment.---## Main Features### Multi-Tenant ArchitectureEach organization has its own isolated workspace.Main tenant-related features:- automatic organization creation during signup;- user-to-organization binding;- organization-scoped clients, services, appointments, audit logs, and analytics;- protection against accessing data from another organization.---### User RolesThe system supports three main roles:| Role | Description ||---|---|| Admin | Manages organization settings, users, services, clients, appointments, finances, and audit logs || Manager | Manages operational data such as clients, services, appointments, and financial analytics || Employee | Works mainly with assigned appointments |Role-based access is applied across the web interface and business logic.---### Authentication and Organization LoginUsers log in using:- username;- password;- organization name or slug.This prevents users from accessing the wrong organization workspace and supports the multi-tenant structure of the system.---### Client ManagementThe client module allows users to:- create clients;- edit client information;- activate or deactivate clients;- search and filter clients;- export client data to CSV.Client records are scoped to the current organization.---### Service ManagementThe service catalog allows users to manage:- service categories;- services;- base service price;- service duration;- active or inactive service status.Service prices are treated as base or estimated prices. The final price of a specific appointment can be set separately.---### Appointment ManagementThe appointment module supports:- creating appointments;- assigning clients, services, and employees;- setting appointment date and time;- changing appointment statuses;- quick status actions from the appointment list;- appointment history tracking;- conflict validation for overlapping appointments;- inline editing of actual appointment price;- filtering and pagination.The system prevents time conflicts for the same employee within the same organization.---### Actual Price and Revenue AnalyticsEach appointment can store an individual actual price after the service is provided.The system supports:- base service price;- actual appointment price;- total revenue calculation;- average check calculation;- paid appointment counting;- financial analytics by filters;- CSV export of financial data.Financial information is available only to Admin and Manager roles.---### Financial AnalyticsThe financial analytics page allows Admin and Manager users to analyze income by:- date range;- service;- employee;- appointment status.The page includes:- total revenue;- average check;- number of paid appointments;- completed appointments without actual price;- grouped analytics by services;- grouped analytics by employees;- grouped analytics by dates;- detailed appointment revenue table;- CSV export.---### DashboardThe dashboard provides a compact overview of the organization workspace:- operational KPIs;- upcoming appointments;- quick actions;- appointment status statistics;- attention-required items;- daily revenue summary for Admin and Manager users;- onboarding checklist for new organizations.---### OnboardingFor newly created organizations, the system displays an onboarding checklist that helps users start working with the system.The checklist includes:- create the first service category;- create the first service;- add an employee;- add a client;- create the first appointment.---### Audit LogThe audit module tracks important system events and changes.It allows authorized users to review:- user actions;- entity changes;- appointment status changes;- organization-scoped audit events.---### CSV ExportThe system supports CSV export for:- clients;- services;- appointments;- financial analytics.CSV exports respect:- organization boundaries;- user roles;- current filters;- employee-specific appointment restrictions.---### REST APIThe project includes read-only REST API endpoints implemented with Django REST Framework.Available API areas include:- clients;- services;- appointments;- dashboard analytics.API access is restricted to authenticated users and respects organization-based data isolation.---## Technology Stack### Backend- Python- Django- Django REST Framework- PostgreSQL- Gunicorn-ready architecture- Python Decouple for environment variables### Frontend- Django Templates- HTML- CSS- Bootstrap-based styling- Vanilla JavaScript for authentication page interactions### Database- PostgreSQL- Organization-scoped relational data model- Database indexes for frequently used organization-scoped queries### Infrastructure- Docker- Docker Compose- Environment-based configuration- PostgreSQL container for local deployment---## Project Structure```textThesis/├── Dockerfile├── docker-compose.yml├── .dockerignore├── .env.example├── requirements.txt├──
